## What I Learned

1. **Eloquent Resources are the serialization layer.** One Resource class = one data shape, used everywhere. No leaking database columns, no inconsistency.

2. **Status codes have semantics.** 201 (Created), 204 (No Content), 401 (unauthenticated), 403 (unauthorized), 422 (validation failed) are not arbitrary—clients rely on them for control flow.

3. **Error envelopes are non-negotiable.** Every failure path (404, 422, 500) must return the same JSON shape. Without this, clients need 10 different error handlers.

4. **Laravel 11 middleware is configured differently.** The `validateCsrfTokens(except: ['api/*'])` array is how you exempt routes from CSRF. Not aliases, not middleware groups—explicit exceptions.

5. **FormRequest `authorize()` runs before validation.** Returning `false` gives 403 Forbidden *before* the rules are checked. This is a gate, not a validation rule.

## What Went Wrong

| What | Why it was wrong | How I fixed it |
|---|---|---|
| CSRF 419 errors on POST | Laravel applies CSRF by default; API routes shouldn't require CSRF tokens | Added `validateCsrfTokens(except: ['api/*'])` to bootstrap/app.php |
| 403 Forbidden on all POSTs | FormRequest authorize() was returning false (leftover from template) | Changed to `return true;` |
| 500 Database error on POST | Schema had NOT NULL `placed_at` column but validation didn't include it | Added `placed_at` field to validation and test payload |
| Middleware conflicts | CheckCustomHeader from Day 3 was blocking API routes | Modified middleware to skip api/* paths |

## Senior Review Findings

Prompt C identified these gaps (none are blockers for Day 7, but matter for Week 3):

1. **Route model binding not used** — show/update/destroy manually call Order::find() instead of using Laravel's implicit binding. Simpler but less idiomatic.

2. **No eager loading strategy visible** — If Order has relations, accessing them in Resource will N+1. Currently no relations, but this matters for Day 6 (Eloquent optimization).

3. **Validation errors (422) shape not tested** — You proved 404 error envelope works, but haven't tested 422. Laravel's default validation response might not match your envelope. **Action item:** test this before Week 3.

4. **placed_at in validation but not in output** — You accept it as input (nullable|date) but OrderResource doesn't expose it. Inconsistent data flow.

5. **No authorization checks** — Any user can CRUD any order. This is expected for Week 2 Day 7; Day 8 adds Sanctum and Policies. But worth noting.
