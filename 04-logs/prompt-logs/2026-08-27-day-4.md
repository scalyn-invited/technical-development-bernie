## Prompt A — Concept Review (0–10 min)

**Prompt used:**
> Explain `foreign keys with onDelete behavior (cascade, restrict, set null)` and `model factories and seeding` to a working developer in under 400 words. Cover what problem each solves, correct usage, and two common mistakes developers make. No exercises, no code beyond short illustrative fragments.

**AI Response Quality:** ⭐⭐⭐⭐⭐ High  
**Validation:** ✅ Checked against Laravel docs; all claims accurate

**Key concepts explained:**
1. **Foreign Keys & onDelete** — Maintain referential integrity; prevent orphaned records
   - `cascade`: Auto-delete children (use when children have no independent meaning)
   - `restrict`: Prevent parent deletion if children exist (use when children need parent)
   - `set null`: Orphan children (use for optional relationships)
2. **Factories** — Generate realistic test/seed data programmatically
3. **Seeders** — Populate database with known state; version-controlled setup

**Common mistakes highlighted:**
- Always choosing `cascade` by default; causes silent data loss
- Using `set null` on NOT NULL columns; causes runtime DB errors
- Hardcoding IDs or foreign keys in seeders instead of using factories

**Output used:** All concepts directly applied to exercise; no rejection needed.
