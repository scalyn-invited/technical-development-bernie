## Prompt C — Review and Challenge, Round 1 (~45 min mark)

**Prompt asked:**
> Here is my solution. Act as a senior reviewer. Identify every weakness, security issue, N+1 query, missed edge case and incorrect assumption. Explain why each one is wrong. Do not rewrite my code. Then ask me five questions about it, one of which should be about a decision I did not consciously make.

**Output quality:** ✅ Strong — identified 7 real findings against the first 9-test version of `OrderApiTest.php`:
1. **Critical:** create-order test never attempted a `user_id` spoofing payload — couldn't distinguish a safe controller from a mass-assignment vulnerability
2. **Significant:** `destroy` authorization tested only from the success side; no non-owner-cannot-delete test
3. Update endpoint entirely untested at the time (later found to already have partial coverage added mid-session)
4. No `assertJsonStructure` test — exact response shape unverified
5. No query-count regression test
6. No true database-free unit test
7. Bundled four invalid fields into a single validation test, reducing failure-localization precision

**Five questions asked back:** included one about an unconscious decision — why `role` was specified for the user in one test (`test_authenticated_user_can_list_their_own_orders`) but omitted in another (`test_user_can_create_an_order`) — correctly flagged as inconsistency rather than deliberate design.

**How validated:** Every finding was tested by writing the actual test and running it, not accepted on the AI's say-so. Findings #1 and #2 (the two security-relevant ones) were prioritised and fixed first.
