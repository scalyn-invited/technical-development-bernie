## Prompt C — schema review (block 45–55)

> Review this schema against the domain. What will I be unable to represent later without a migration?

**Output quality:** high and directly usable. Eight limits returned, all eight recorded verbatim in `TECHNICAL-NOTES.md` §5.

**How it was validated:** each claim was checked against the actual migration files and, where checkable, against the running database.

| Finding | Real? | Action |
|---|---|---|
| Unique `user_id` prevents a second programme cycle | Yes — confirmed in the migration | Recorded. Deliberate; management scoped to one cycle. |
| No `plan_skills` table, so plan membership is inferred from baseline rows | Yes | Recorded as **the** deliberate scope cut (§5.2). |

| `unique(plan, week_number)` permits only one focus skill per week | Yes | Recorded. |

| `cascadeOnDelete` + no soft deletes means deleting a user erases the whole record | Yes | Recorded. **Changed how I describe the schema** — this is data loss with no recovery path. |
| `decimal(5,2)` accepts up to 999.99; there is no database-level 0–100 check | Yes — verified against the column definition | Recorded. **The most useful finding of the day**: the day card says "0–100" and I had written the column believing it enforced that. |
| `key_gaps` / `weekly_focus` are free text, so gap analysis is not queryable | Yes | Recorded. |

No false positives this session. The review was asked a narrow question and answered it narrowly, which is why it was worth more than a general "review my schema".

## AI output that was wrong

1. **`php artisan tinker --execute="require '<file>';"`** — proposed as the way to run the relationship proof. It **printed the file source and executed nothing**, while exiting successfully. If the output had been skimmed rather than read, an empty verification would have been filed as a passing one. Replaced with a script that bootstraps the console kernel directly and genuinely runs.
2. **A `/tmp/...` path** was used for that script on a Windows machine. Bash resolved it; PHP did not. Failed loudly, but the lesson is the quieter one: "it ran" and "it ran against what I think it ran against" are separate claims, and only the second is evidence.

Both entries belong to framework §12's *AI-assisted development* assessment area: the value was in verifying the tooling's own output, not only the code it produced.

## Standing note on this session's method

The schema was **specified in the Day 10 card before the session opened** — every column, type, nullability, foreign-key behaviour, unique constraint and index. The AI implemented to that specification rather than designing it. Accepted AI suggestions, each reviewed before use: the `app/Enums` backed-enum approach, the `decimal:2` cast (scores stay strings, so no float drift), and the three-stage seeded dataset. Everything the AI wrote was proven by execution before being logged as done.
