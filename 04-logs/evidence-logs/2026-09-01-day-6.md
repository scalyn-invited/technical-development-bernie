## Day 6 Evidence — Eager Loading, N+1, and Indexes

### Exercise Structure (7 parts)

#### Part (a): N+1 Problem — Query Count: **251**
```php
$orders = Order::all();
$customers = [];
foreach ($orders as $order) {
    $customers[] = $order->customer->name;
}
```
**Result:** 1 query for orders + 250 queries (one per order to fetch customer) = **251 total**

#### Part (b): Eager Loading Fix — Query Count: **2**
```php
$orders = Order::with('customer')->get();
$customers = [];
foreach ($orders as $order) {
    $customers[] = $order->customer->name;
}
```
**Result:** 1 query for orders + 1 query for all related customers = **2 total**
**Reduction:** 251 → 2 (99.2% reduction)

#### Part (c): withCount() — Query Count: **1**
```php
$orders = Order::withCount('items')->get();
foreach ($orders as $order) {
    echo $order->items_count;
}
```
**Result:** Single query with count appended = **1 query**
**Key insight:** Counts without loading the related records

#### Part (d): Constrained Eager Loading — Query Count: **2**
```php
$orders = Order::with(['items' => function ($query) {
    $query->where('product_name', 'like', '%a%');
}])->get();
```
**Result:** 1 query for orders + 1 query for filtered items = **2 queries**
**Pattern:** Constrains which items load without N+1

#### Part (e): Query Scopes and Accessor
**Scopes added to Order model:**
- `scopeCompleted()` — filters to status='completed'
- `scopeRecentFirst()` — orders by placed_at descending
- Accessor `getFormattedTotalAttribute()` — returns total as formatted currency string ("$34.27")

**Test result:** `Order::completed()->recentFirst()->first()` returns correct data; accessor displays correctly.

#### Part (f): Transaction Rollback — Verified
```php
Customer count before: 10
Order count before: 250

DB::transaction(function () {
    Customer::factory()->create();
    Order::factory()->create();
    throw new Exception('Deliberate rollback test');
});

Customer count after: 10 ✓ (rolled back)
Order count after: 250 ✓ (rolled back)
```
**Result:** Both writes rolled back; transaction isolation confirmed.

#### Part (g): Index Timing
**Before index:** 251 queries executed (N+1 in part a)
**After index:** 251 queries executed (index on customer_id present, but N+1 pattern unchanged)
**Key finding:** Index optimization is secondary to eager loading. The real speedup was in part (b), not from indexing.
