## Schema Design

### Tables

**teams**
```sql
id (bigint, pk)
name (string, unique)
created_at, updated_at
```

**venues**
```sql
id (bigint, pk)
name (string)
address (string)
created_at, updated_at
```

**players**
```sql
id (bigint, pk)
team_id (bigint, fk → teams.id, restrictOnDelete)
name (string)
season (unsignedInteger)
created_at, updated_at
```

**matches**
```sql
id (bigint, pk)
home_team_id (bigint, fk → teams.id, restrictOnDelete)
away_team_id (bigint, fk → teams.id, restrictOnDelete)
venue_id (bigint, fk → venues.id, restrictOnDelete)
scheduled_at (dateTime)
home_score (unsignedInteger, nullable)
away_score (unsignedInteger, nullable)
winner_team_id (bigint, fk → teams.id, nullable, restrictOnDelete)
notes (text, nullable)
created_at, updated_at
```

---

## Foreign Key Strategy

**Decision:** All foreign keys use `restrictOnDelete()` instead of `cascade`.

**Rationale:**
- Matches are historical records; deleting a team should not silently delete match history
- Prevents accidental data loss through cascading deletes
- Forces explicit application logic to handle team deletion (e.g., retire the team rather than erase it)
- Query integrity: reports like "how many matches has this team played?" remain accurate

**Trade-off:**
- Cannot delete a team if it's referenced in any match (including historical ones)
- Acceptable for this schema; application must handle retired teams separately

## Indexes & Justification

| Table | Column(s) | Reason | Query Example |
|-------|-----------|--------|----------------|
| players | team_id | Filter by team when building roster | `SELECT * FROM players WHERE team_id = 5` |
| matches | (home_team_id, away_team_id) | Find all matches for a team (home or away) | `SELECT * FROM matches WHERE home_team_id = 5 OR away_team_id = 5` |
| matches | scheduled_at | Filter upcoming/past matches | `SELECT * FROM matches WHERE scheduled_at > NOW()` |

**Why no index on:**
- `venue_id`: Only 3 venues; full table scan acceptable
- `winner_team_id`: Small percentage of matches have results; low cardinality

## Models & Relationships

### Team
```php
class Team extends Model {
    public function players() { return $this->hasMany(Player::class); }
    public function homeMatches() { return $this->hasMany(MatchGame::class, 'home_team_id'); }
    public function awayMatches() { return $this->hasMany(MatchGame::class, 'away_team_id'); }
}
```

### Player
```php
class Player extends Model {
    public function team() { return $this->belongsTo(Team::class); }
}
```

### MatchGame
```php
class MatchGame extends Model {
    public function homeTeam() { return $this->belongsTo(Team::class, 'home_team_id'); }
    public function awayTeam() { return $this->belongsTo(Team::class, 'away_team_id'); }
    public function venue() { return $this->belongsTo(Venue::class); }
    public function winner() { return $this->belongsTo(Team::class, 'winner_team_id'); }
}
```

**Note:** Team model uses explicit foreign key names because there are two `belongsTo(Team::class)` relationships that must be distinguished.

## Bugs Found & Fixed During Implementation

### Bug #1: Model Naming — `Match` is a Reserved Keyword

**Error:**
```
ParseError: syntax error, unexpected token "::", expecting "("
  at database\seeders\DatabaseSeeder.php:52
```

**Root Cause:** `match` is a reserved keyword in PHP 8+ (used for match expressions). Cannot use `class Match extends Model`.

**Fix:** Renamed model to `MatchGame` to avoid keyword collision.

**File:** Renamed `MatchModelFactory.php` → `MatchGame.php`

---

### Bug #2: Factory File Naming Mismatch

**Error:**
```
Class "Database\Factories\MatchGameFactory" not found
```

**Root Cause:** Factory file was named `MatchFactory.php` but model was `MatchGame`. Laravel's factory auto-discovery expects exact name match.

**Fix:** Renamed `database/factories/MatchFactory.php` → `database/factories/MatchGameFactory.php` and updated class name inside.

---

### Bug #3: Old Class References in Relationships

**Location:** `Team.php`, lines 23 & 28

**Code:**
```php
public function homeMatches() {
    return $this->hasMany(MatchModel::class, 'home_team_id');
}
```

**Issue:** References `MatchModel::class` (old name) instead of `MatchGame::class` (new name).

**Fix:** Updated both methods to use `MatchGame::class`.

---

## Lessons from Bugs

1. **Reserved keywords matter** — PHP 8 reserves common words; test with fresh model names
2. **Factory naming is strict** — Auto-discovery depends on exact class/file name match
3. **Refactor all references** — When renaming a class, search the entire codebase for old references
