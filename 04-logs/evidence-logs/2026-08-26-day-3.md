```php
public function handle(Request $request, Closure $next): Response
{
    if (!$request->hasHeader('X-Custom-Header')) {
        return response()->json([
            'error' => 'Missing required header: X-Custom-Header'
        ], 400);
    }
    return $next($request);
}
```

## Exercise 3B — Debugging (4 Bugs Found & Fixed)

### Bug #1: Route Ordering Conflict

**What:** `/posts/create` route came AFTER `/posts/{post}` dynamic route

**Original code:**
```php
Route::get('/posts/{post}', [BuggyPostController::class, 'show']);
Route::get('/posts/create', [BuggyPostController::class, 'create']);
```

**Impact:** Request to `/posts/create` matched `{post}` parameter first, treated 'create' as an ID, returned 404

**How diagnosed:** `php artisan route:list` showed route order; browser test to `/posts/create` returned 404

**Root cause:** Dynamic route segments `{param}` match any string, must come AFTER specific routes

**Fix:** Reorder routes — specific routes first:
```php
Route::get('/posts/create', [BuggyPostController::class, 'create']);
Route::get('/posts/{post}', [BuggyPostController::class, 'show']);
```

**Status:** ✅ Fixed

---

### Bug #2: Wrong Route Parameter Binding

**What:** `show()` method signature was `string $post_id` but route uses `{post}`

**Original code:**
```php
public function show(string $post_id)
{
    $post = Post::findOrFail($post_id);
    return $post;
}
```

**Impact:** Laravel couldn't use implicit binding; manual fetch required; binding mismatch between route `{post}` and parameter name `$post_id`

**How diagnosed:** cURL to `/posts/1` failed; compared to `edit()` which worked fine and used `Post $post`

**Root cause:** Implicit binding requires:
1. Route parameter name matches type-hinted parameter name, OR
2. Type hint the model and Laravel knows to fetch by ID automatically

**Fix:** Use implicit binding:
```php
public function show(Post $post)
{
    return response()->json(['message' => 'Show post', 'post' => $post]);
}
```

**Status:** ✅ Fixed

---

### Bug #3: Wrong Return Type

**What:** `show()` returned raw Model instance instead of JSON response

**Original code:**
```php
return $post;  // Returns PHP object, not JSON
```

**Impact:** Response was Model object serialized as JSON by Laravel, but inconsistent with other methods which explicitly wrapped responses

**How diagnosed:** Compared `show()` return with `edit()` which used `response()->json()`; inconsistency visible

**Root cause:** Controller methods should have consistent return types for API consistency

**Fix:** Wrap in response()->json():
```php
return response()->json(['message' => 'Show post', 'post' => $post]);
```

**Status:** ✅ Fixed

---

### Bug #4: Edit Route Position

**What:** `/posts/{post}/edit` came AFTER `/posts/{post}` dynamic route

**Original code:**
```php
Route::get('/posts/{post}', [BuggyPostController::class, 'show']);
Route::get('/posts/{post}/edit', [BuggyPostController::class, 'edit']);
```

**Impact:** Request to `/posts/1/edit` matched `{post}` first with value `1`, then looked for `edit` sub-action that doesn't exist

**How diagnosed:** Browser test to `/posts/1/edit` failed; `route:list` showed order

**Root cause:** Static path segments must come before dynamic ones at the same level

**Fix:** Reorder — more specific paths first:
```php
Route::get('/posts/{post}/edit', [BuggyPostController::class, 'edit']);
Route::get('/posts/{post}', [BuggyPostController::class, 'show']);
```

**Status:** ✅ Fixed

## Fixed Routes — Final Version

```php
// Specific routes first, then dynamic routes
Route::middleware('check-custom-header')->group(function () {
    Route::get('/posts', [BuggyPostController::class, 'index']);
    Route::get('/posts/create', [BuggyPostController::class, 'create']);
    Route::post('/posts', [BuggyPostController::class, 'store']); 
    Route::get('/posts/{post}', [BuggyPostController::class, 'show']); 
    Route::get('/posts/{post}/edit', [BuggyPostController::class, 'edit']);
    Route::put('/posts/{post}', [BuggyPostController::class, 'update']);
    Route::delete('/posts/{post}', [BuggyPostController::class, 'destroy']);
});
```

**Final verification:** `php artisan route:list` shows all routes in correct order, all working.
